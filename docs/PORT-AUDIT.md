# Audit: the thirteen behaviours against the real Jarvis

Verdicts are from reading the real code at 07ec0465, with the measurements taken by running it.
"Prototype" refers to the standalone branch, used only as reference.

| #   | Behaviour                                                               | Verdict                                  | Evidence                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | ----------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Continuous execution: plan → build → verify → review → repair → deliver | **Richer here already**; one gap         | All phases real (`task-decomposition.ts`), repair rounds bounded by `maxRepairRounds` (`orchestrator.ts:810`). Gap: `MissionOrchestrator.tick` has **no timer** — it runs only on claim/report, so a mission whose last task ended without a terminal report sits still (`task-worker-service.ts:282`, `:834`).                                                                                   |
| 2   | "evaluate only" punctuation                                             | **ABSENT — and it built things**         | FIXED in c45adcc. Measured before: `kind:'work'`, `noBuildYet:false`, `describesNewProject:true` → project + repo + mission.                                                                                                                                                                                                                                                                      |
| 3   | Continuation changes ("carry on and add dark mode")                     | **ABSENT**                               | `CONTINUE` (`interpretation.ts:347`) is `^`-anchored with no lookahead; the payload half is discarded. `ConversationService.followUp` has no `continue` branch (`:592`).                                                                                                                                                                                                                          |
| 4   | Retry ownership                                                         | **Sound already**                        | Four bounded mechanisms, deliberately layered: transport (`client.ts:234`), attempt budget (`factory-drizzle.ts:431`, `maxAttempts:1`), reclaim (`RECLAIM_GRACE=1`), supervisor backoff. They do not multiply: a _failed unit of work_ is never auto-retried.                                                                                                                                     |
| 5   | Bounded retry                                                           | **EXISTS**                               | Every bound is a named constant.                                                                                                                                                                                                                                                                                                                                                                  |
| 6   | Gate exceptions resolving jobs                                          | **TWO STRANDING HOLES**                  | (a) `TaskRunner.fail` swallows its own report failure and a fatal `emit` throw escapes to `workLoop`, so the task never reports terminal (`task-runner.ts:1213`). (b) A throw between `claimNext` and `buildAssignment` leaves the task `claimed` for ever — `reclaimAbandoned` skips it because the worker is alive (`task-worker-service.ts:282`, `:541`).                                      |
| 7   | Error classification respecting status and codes                        | **ONE PROSE-ONLY CLASSIFIER**            | `isRetryable` (`runtime/claude-agent-sdk.ts:598`) reads only the message: an Anthropic 403 whose text says "timeout" is retried. `classifyFailure` (`mission-runner.ts:1322`) ignores `GitError` and `ControlPlaneError.code`. GitHub's own classifier is correct and is the model to copy (`providers/github/client.ts:203`).                                                                    |
| 8   | Validated telemetry, correct percent scaling                            | **Validation EXISTS; one scaling gap**   | `percentage()` refuses NaN/negative/>100 rather than clamping (`claude-telemetry.ts:149`) — the prototype's 100× bug cannot occur. Gap: a 0..1 fraction is accepted verbatim and renders as "100% left" on an exhausted account.                                                                                                                                                                  |
| 9   | Stale and unavailable usage states                                      | **PARTIAL**                              | `ObservationQuality` distinguishes measured/estimated/stale/unknown. Gap: `CapacityWindowView` carries no `observedAt`, so no surface can say _how_ stale (`capacity-view.ts:105`).                                                                                                                                                                                                               |
| 10  | Pacing on real usage                                                    | **EXISTS, five layers**                  | `decideCapacity` → `maxNewWork` narrows the operator's ceiling (`operator-service.ts:783`) and gates reasoning claims (`worker-service.ts:866`). Not display-only.                                                                                                                                                                                                                                |
| 11  | Concise first-person replies                                            | **EXISTS**                               | Reply text is produced in one place per turn kind and is already one or two sentences.                                                                                                                                                                                                                                                                                                            |
| 12  | Voice dedup and mute                                                    | **PARTIAL — messages are silently lost** | Dedup against replay is sound (`operating-drizzle.ts:187`, pinned by `spoken-once.test.ts`). But the client claims up to 6 events and loops `speak()`, and `speak()` opens with `speechSynthesis.cancel()` — only the last is heard, and all are already stamped spoken. Mute is client-only; the route claims and stamps for any caller.                                                         |
| 13  | Chat reference resolution and mid-project changes                       | **PARTIAL, with a build hazard**         | Ordinals work (`context.actions`). "change that" does not: `focusedProjectId` is declared and validated but read nowhere. A change is always a new mission, and an unmatched subject can provision a _second project_. Worse: a `stale` follow-up is routed into acceptance (`conversation-service.ts:599`), so an ordinal typed with no list on screen can accept and build a standing proposal. |

## What this means

Most of what I was asked to port already exists here, usually in a better form than the prototype's.
Porting my versions over them would be a downgrade. So the work is: fix the genuine defects the
audit found, and lock the existing guarantees into the real suites.
